## 1. Dataset overview

* File grid: **4255 storm rows × 360 time slots**; only the first `numobs` cells per storm are real observations.
* **Raw records: 249,084 observations from 4,255 storm rows**; seasons 1884–2026; time span 1884-06-24 16:00:00+00:00 → 2026-10-18 00:00:00+00:00 (UTC).
* Study period 1980–2024: **104,927 observations from 1,471 storms**.
* `LAT` range 0.1…70.1 °N; `LON` range 56.0…266.9 °E (**file convention 0–360°E**, see §5).
* Duplicate (SID, TIME) pairs: **0** (confirmed: none found).
* Time encoding: `time` = days since 1858-11-17 (`TIME_FILL=-9999000.0`); per-observation `iso_time` strings (UTC) parsed directly; NetCDF `_FillValue=-9999` mapped to missing.

## 2. Structure of the data

* Distinct main-track storms (all years): 4,107 (non-main: 148 distinct storms — see `tables/06_track_type.csv`).
* Per-observation basin mix shows storms transitioning out of WP: EP and NI observations exist inside this WP extract (see `tables/07_basin.csv`), so basin filtering **must be per observation**, not per storm.
* Observations-per-storm and duration distributions: see `figures/02_*`, `figures/10_*`, `tables/04_*`.
* Gap analysis (all years; within-storm consecutive pairs): **1 h: 3.6%, 2 h: 3.5%, 3 h: 92.9%** — the native grid is a complete 3-hourly lattice (IBTrACS fills 3-hourly fixes, see IFLAG), so the 6-hourly subset keeps roughly one in two timestamps by design (see `figures/09_*`, `tables/08_*`).

* Invalid positions: none outside LAT∈[−90,90] / LON∈[0,360] beyond NaNs (see `tables/13_*`); LAT/LON are jointly present for every `numobs` cell.
* Out-of-order timestamps within a storm: counted in `tables/13_*` (detection only; confirmed 0).
* Suspicious jumps: consecutive displacement > 1000 km flagged (`SUSPICIOUS_JUMP`, see `tables/13_*`; confirmed 0); extreme recomputed translation > 80 kts flagged (25 obs). **Nothing was removed.**
* IFLAG is one character **per agency** (15 agencies, order in file metadata). 62.6% of raw obs carry a `P` (position-interpolated) mark from ≥1 agency and 45.8% an `O` (original) mark — marks coexist because agencies report independently (see `tables/09_*`). The 3-hourly lattice is therefore heavily agency-interpolated: preprocessing should prefer synoptic 6-hourly fixes and explicitly handle/test `P`-dominated timestamps — recommendation, not applied here.
* Longitude: stored **0–360°E** (max 266.9). There is no jump at 180° in storage; a jump only appears if wrapped to −180…180 for display. All distances/motion here use unwrapped longitudes + haversine; track plots break lines at gaps > 6.5 h so segments are never joined by straight artefacts (see `figures/05_*`, `figures/08_*`).

## 4. STORM_SPEED / STORM_DIR — derivation and leakage assessment

* File metadata gives units/conventions but **no formula**; per IBTrACS practice these are translation vectors derived from successive positions (agency guidance, not independently observed).
* Empirical check (study period, n=103,456): Pearson r(reported, past-only recomputed) = **0.9817**; mean residual (reported − past-only) and p90 in `tables/14_*`. In practice the file values track a backward difference closely — but that does not make them causal (next point). Residuals cluster at integer offsets because file STORM_SPEED is integer-rounded while the recomputed value is continuous (see `figures/15_*`).
* Structural leakage proof: each storm's first observation has **no past** (past-only speed = NaN by construction for all 4,255 storm rows), yet file STORM_SPEED is missing in only 1 study-period obs — i.e. it is populated where no past exists, so it cannot be a pure backward difference and must use centred/forward information (**future leakage relative to a causal input**).
* **Recommendation:** do NOT feed file STORM_SPEED/STORM_DIR as inputs without recomputing them causally (backward difference from past positions only, masking first obs + post-gap obs). Compare both variants in preprocessing ablations. Direction is circular — encode as (sin, cos) later, not raw degrees.

## 7. Leakage risks and preprocessing recommendations

1. **STORM_SPEED/STORM_DIR leakage** (above): recompute causally; never use file values as inputs without proof of causality.
2. **Interpolation leakage**: IFLAG `P` fixes are synthetic 3-hourly fills; restrict training segments to original (`O`) fixes or explicitly flag them.
3. **Basin/track filtering**: filter per observation (basin) and per storm (track type) exactly as F2/F3; document the non-main exclusion decision.
4. **Split discipline**: split by storm (and by season block 1980–2016 / 2017–2020 / 2021–2024), never by window, to avoid same-storm windows leaking across sets.
5. **Gap handling**: build windows only inside exact-6 h runs; mask loss at horizons crossing any residual gap.
6. **Circular/longitude care**: model inputs should use displacements or (sin,cos) direction and unwrapped/relative longitudes, not raw 0–360 values.
7. **No imputation in EDA**: all numbers above are computed on observed data; preprocessing choices (dropping vs masking) belong to Task 2.
